# AI PR Summarizer

A GitHub Action that automatically summarizes pull request diffs using OpenAI `gpt-4o-mini` and posts a structured, developer-friendly comment back on the PR.

## Features

- Runs on `pull_request` events (`opened`, `synchronize`).
- Fetches the raw diff via the GitHub API.
- Truncates diffs to 8,000 characters to stay within token limits.
- Sends the diff to OpenAI with a structured system prompt.
- Posts a Markdown summary comment on the PR.
- Includes robust error handling and clear failure messages.

### 1. Install dependencies

```bash
npm install
```

### 2. Type-check the source

```bash
npm run lint
```

### 3. Build the bundle

```bash
npm run build
```

This uses `@vercel/ncc` to compile `src/index.ts` and all dependencies into a single `dist/index.js` file, which is what GitHub Actions executes.

> **Important:** Always commit `dist/index.js` (and `dist/licenses.txt`) after every source change. GitHub Actions does not run `npm install` or `npm run build` automatically; it uses the committed bundle.

## Deploy to a Test GitHub Repository

### Option A: Push this repo and use it as a local action

1. Create a new repository on GitHub (e.g. `my-org/ai-pr-summarizer`).
2. Push this project to the default branch:

   ```bash
   git init
   git add .
   git commit -m "Initial ai-pr-summarizer MVP"
   git branch -M main
   git remote add origin https://github.com/<owner>/<repo>.git
   git push -u origin main
   ```

3. In the **same repository**, create `.github/workflows/pr-summarizer.yml` (or use the included one):

   ```yaml
   name: AI PR Summarizer

   on:
     pull_request:
       types: [opened, synchronize]

   permissions:
     contents: read
     pull-requests: write
     issues: write

   jobs:
     summarize:
       runs-on: ubuntu-latest
       steps:
         - name: Summarize PR with AI
           uses: ./
           with:
             openai-api-key: ${{ secrets.OPENAI_API_KEY }}
             github-token: ${{ github.token }}
   ```

4. Add `OPENAI_API_KEY` to the repository secrets:
   - Go to **Settings** → **Secrets and variables** → **Actions**.
   - Click **New repository secret**.
   - Name: `OPENAI_API_KEY`
   - Value: your OpenAI API key.

   > **Note:** GitHub reserves the `GITHUB_` prefix for built-in secrets and variables. Do not create custom secrets named `GITHUB_*` (e.g. `GITHUB_PAT`). The action uses `github.token` (the built-in `GITHUB_TOKEN`) by default, so no custom GitHub token secret is required.

5. Open a new pull request. The action will run and post an AI-generated summary comment.

### Option B: Publish and reuse across repositories

To use the action in a different repository, publish it to the first repository and reference it by version tag:

```yaml
- name: Summarize PR with AI
  uses: <owner>/<repo>@v1
  with:
    openai-api-key: ${{ secrets.OPENAI_API_KEY }}
    github-token: ${{ github.token }}
```

For a reusable action, create a release tag after every update and ensure `dist/index.js` is committed:

```bash
npm run build
git add dist src package.json action.yml tsconfig.json .github/workflows
git commit -m "Build and release v1.0.1"
git tag -a v1.0.1 -m "Release v1.0.1"
git push origin main --tags
```

## Inputs

| Input | Required | Default | Description |
|-------|----------|---------|-------------|
| `openai-api-key` | yes | — | OpenAI API key for calling `gpt-4o-mini`. |
| `github-token` | yes | `${{ github.token }}` | Built-in GitHub token (`github.token`) with permission to read the PR and post comments. |

## Permissions Required

The workflow needs the following permissions:

- `contents: read` — to read repository metadata.
- `pull-requests: write` — to fetch the PR diff and post comments.
- `issues: write` — PR comments are technically issue comments.

## How It Works

1. **Input extraction** — reads `openai-api-key` and `github-token`.
2. **Context validation** — verifies the action is triggered by a `pull_request` event and extracts `owner`, `repo`, and `pull_number`.
3. **Diff fetch** — calls `octokit.rest.pulls.get` with `mediaType: { format: 'diff' }`.
4. **Diff truncation** — caps the diff at 8,000 characters to avoid exceeding token limits.
5. **OpenAI summary** — sends a structured prompt to `gpt-4o-mini` and receives Markdown output.
6. **Comment posting** — publishes the summary as a PR comment using `octokit.rest.issues.createComment`.

## Customization

- Edit `src/index.ts` to change the model, prompt, temperature, or diff size limit.
- Rebuild and commit `dist/` after every change.
